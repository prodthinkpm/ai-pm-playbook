第 8 课：偏好数据、DPO 和 RLHF ​

本课目标：理解什么是偏好数据，它和 SFT 数据有什么不同，以及 DPO 和 RLHF 这两种"对齐"方法的工作原理、区别和选型思路。

1. 先说结论 ​

第 7 课我们讲了 SFT——用"问题-标准答案"对训练模型。但 SFT 有一个大问题：

一个答案"正确"不等于"用户更喜欢"。

用户说"写一首关于夏天的诗"。SFT 给的答案是"夏天很热，太阳很大"。这个答案没错，但用户可能更喜欢"蝉鸣撕开午后的慵懒，树影在柏油路上慢慢融化"。第一个答案"对"，第二个答案"好"。SFT 只能学"对"，但学不会"好"。

偏好对齐（Preference Alignment） 就是让模型不只输出正确的回答，还要输出用户更喜欢的回答。

三种主流方法：

方法一句话理解需要什么
SFT学标准答案问题-回答对
DPO学用户偏好问题 + 好回答 + 差回答
RLHF找个裁判打分，再优化问题 + 好回答 + 差回答 + 奖励模型

简单说：SFT 教模型"及格"，DPO 和 RLHF 教模型"优秀"。

2. 生活类比 ​

类比 1：教孩子写作文 ​

SFT = 给孩子一堆"优秀作文"让他模仿，但不知道哪句好、哪句差。 DPO = 你拿着好作文和差作文说："记住，这篇好，这篇差。"孩子自己琢磨出区别。 RLHF = 请一个语文老师（奖励模型）给孩子打分。孩子不断修改，直到分越来越高。

类比 2：训练搜救犬 ​

SFT = 给狗看 100 张"受伤的人"的照片说"这是要找的人"。 DPO = 同时放两张照片说"左边是真正需要救的人，右边不是，选左边"。 RLHF = 训犬师当裁判，每次找到人给奖励或批评，狗不断调整策略。

核心区别：SFT 学"什么是正确的"，DPO 学"什么是更好的"，RLHF 通过"反馈循环"持续优化。

3. 什么是偏好数据？ ​

SFT 数据是"问题 → 标准答案"。偏好数据是"问题 → 多种回答 → 标注哪个更好"。

偏好数据不关心"哪个是对的"，只关心"哪个更受喜欢"。

三种常见形式 ​

形式一：二元对比（Pairwise）——DPO 最常用的形式

text
问题：请解释什么是区块链。
回答 A（好）：区块链是一种分布式账本技术，数据存储在多个节点上…
回答 B（差）：区块链就是比特币用的技术，很安全。
标注结果：A > B

形式二：排序（Ranking）——RLHF 训练奖励模型常用

text
问题：如何提高团队效率？
回答 1：每天开会…（第 3 名）
回答 2：明确目标和优先级…（第 1 名）
回答 3：用 Jira 管理任务…（第 2 名）

形式三：打分（Scalar Rating）

text
回答 1：我们的产品很好用。（2/5）
回答 2：智能水杯采用316不锈钢内胆，App测温，续航30天。（5/5）

4. 什么是 DPO（Direct Preference Optimization）？ ​

一句话定义 ​

DPO 是一种不需要额外训练奖励模型，直接用偏好数据优化模型的方法。

核心思想 ​

  1. 对于同一个问题，你给了"好回答"和"差回答"
  2. 模型同时学习两件事：
    • 提高生成"好回答"的概率
    • 降低生成"差回答"的概率

"同样的 prompt，给好回答的路径加推力，给差回答的路径踩刹车。"

训练流程 ​

text
开始：一个已经 SFT 过的模型
   ↓
准备数据：[问题, 好回答, 差回答]
   ↓
对每个数据点：让模型看好回答 → 学习模仿
               让模型看差回答 → 降低这个方向的概率
               两个方向的调整同时进行
   ↓
重复直到模型更倾向于输出好回答

为什么 DPO 流行？ ​

2023 年由斯坦福团队提出，迅速流行的原因：

对比DPORLHF
需要另一个模型？❌ 不需要✅ 需要奖励模型
训练复杂度⭐（简单）⭐⭐⭐（复杂）
算力成本低中高
稳定性稳定不稳定
对齐效果好好（可能略好）

2024 年后，Llama 3、Mistral 等开源模型都选择用 DPO 而不是 RLHF。

5. 什么是 RLHF（Reinforcement Learning from Human Feedback）？ ​

一句话定义 ​

RLHF 是用人类偏好训练一个"评分裁判模型（奖励模型）"，然后用这个裁判去指导大模型优化。

经典三步法（来自 OpenAI InstructGPT 论文） ​

第一步：SFT——先用高质量问答数据做指令微调。

第二步：训练奖励模型（Reward Model）

text
收集偏好数据：[问题, 回答 A, 回答 B, 标注：A>B]
   ↓
训练一个专门的打分模型
   ↓
任务：给任意"问题+回答"组合打分
   ↓
目标：人类觉得好的回答分数高，差的回答分数低

第三步：强化学习微调（PPO 阶段）

text
策略模型生成回答 → 奖励模型打分 → PPO 算法更新策略模型
   ↓
同时加 KL 惩罚，不让策略模型偏离 SFT 模型太远
   ↓
重复直到稳定输出高分回答

RLHF 的优缺点 ​

优点缺点
对齐效果可能更好训练复杂，需要调很多参数
奖励模型可反复使用需要训练和维护奖励模型
理论上更灵活容易"奖励欺骗"（模型刷分而不是变好）
适合微妙偏好算力是 DPO 的 3-5 倍

RLHF 是大玩家的选择。对于大部分团队，DPO 是更实际的方案。

6. 为什么 RLHF 需要奖励模型？ ​

人类打分的三个问题 ​

  1. 太慢：人类看一段回答几十秒，模型一秒生成几十条
  2. 太贵：ChatGPT 训练用了数万小时人工标注
  3. 不一致：A 觉得幽默好，B 觉得严肃好

奖励模型 = 自动评委 ​

text
输入：[问题, 回答] → 奖励模型 → 输出：一个分数（如 0.92）
  • 一秒打分几千条
  • 分数稳定一致
  • 一次训练，反复使用

奖励模型本身也是一个语言模型，它学习"好回答→高分，差回答→低分"。

奖励模型的质量直接决定了 RLHF 的上限。裁判不行，选手再好也没用。

7. 对比：SFT vs DPO vs RLHF ​

维度SFTDPORLHF
目标学会回答问题偏向用户偏好更优偏好对齐
数据要求问题+好回答问题+好+差回答问题+好+差回答（更多）
额外模型不需要不需要需要奖励模型
训练成本低低-中高
效果上限一般好可能更好
稳定性稳定稳定不稳定
适合团队所有团队中小团队大公司/研究团队

选型决策树 ​

text
只有"问题-回答"数据？          → 是 → SFT
有"好 vs 差"对比数据？         → 是 → 往下
充足的 GPU 和工程团队？         → 是 → 尝试 RLHF
对细微偏好要求极高（创意写作）？  → 是 → RLHF 上限更高
其余情况                        → DPO 完全够用

对于 90% 的产品场景，SFT + DPO 已经足够。RLHF 的边际收益往往不值得额外成本。

8. 偏好数据集的格式 ​

二元对比格式（DPO 标准格式） ​

json
{
  "prompt": "请用一句话解释什么是机器学习",
  "chosen": "机器学习是让计算机从数据中自动学习规律…",
  "rejected": "机器学习是一种技术。"
}

Hugging Face 的 TRL 框架原生支持这种格式。

排序格式（RLHF 训练奖励模型用） ​

json
{
  "prompt": "如何提高睡眠质量？",
  "responses": ["早睡早起。", "保持规律作息，远离屏幕…", "睡前喝牛奶。"],
  "ranking": [2, 1, 3]
}

打分格式 ​

json
{
  "prompt": "写一段产品文案",
  "response": "我们的产品采用了最新的 AI 技术……",
  "rating": 4
}

多轮对话偏好格式 ​

json
{
  "prompt": "帮我写个 Python 脚本。\n用户：要做什么？\n助手：读取 CSV 生成统计报告。",
  "chosen": "```python\nimport pandas as pd\nprint(df.describe())\n```",
  "rejected": "用 Excel 打开看看就行。"
}

实际工作中，二元对比格式（chosen/rejected）最常用。

9. 开源偏好数据集 ​

数据集规模特点推荐用途
HelpSteer~35kNVIDIA 发布，多维度打分DPO 入门首选
UltraFeedback~64kOpenBMB 发布，每个指令 4 个回答中文友好
HH-RLHF（Anthropic）~160k最早的大规模 RLHF 数据集RLHF 研究标准
OpenAssistant~10k 对话社区贡献，多语言多轮对话偏好
Nectar~180kGPT-4 作为裁判生成大规模低成本

如何选择？ ​

  • 刚入门：HelpSteer（数据干净、格式标准）
  • 中文场景：UltraFeedback 首选
  • 研究 RLHF：HH-RLHF 是经典选择
  • 预算有限：Nectar（GPT-4 自动标注）

注意：开源数据集的偏好标准可能和你的产品场景不同。

10. 常见陷阱 ​

陷阱 1：偏好数据的"噪音" ​

同一个回答，A 觉得 5 分，B 觉得 2 分。模型学到混乱信号。

解决：多人标注取多数、提供清晰标准、用对比替代打分。

陷阱 2：偏好过度，模型变"怂" ​

回答越来越短，过度回避风险，丧失创意。

解决：加 KL 惩罚、结合 SFT 数据训练、监控回答长度。

陷阱 3：奖励欺骗 ​

模型发现"末尾加'希望这能帮到你'"分数会高 → 每个回答都加 → 分高了但体验差了。

解决：多种指标评估、定期人工评估、更新奖励模型。

陷阱 4：偏好数据质量比 SFT 更重要 ​

一条标注错误的偏好数据，破坏力是 SFT 中一条错误数据的 5-10 倍。

因为偏好数据教的是"方向"，方向错了越跑越远。

陷阱 5：忽视计算成本 ​

方法GPU 小时（7B 模型，A100）
SFT50-100 小时
DPO50-100 小时
RLHF（含奖励模型训练）200-400 小时

RLHF 调参周期也更长——可能需要 3-5 次实验。

陷阱 6："无辜的差回答" ​

好回答：Python 是一种高级编程语言，语法简洁，适合数据科学和 Web 开发。 差回答：Python 是一种编程语言。

"差回答"本身没错，只是相比之下不够好。但如果有事实错误，问题更大。

11. 行业真实案例 ​

ChatGPT / InstructGPT（OpenAI） ​

做法（来自 InstructGPT 论文）：

  1. SFT：1.3 万条人工标注数据微调 GPT-3
  2. 奖励模型：3.3 万条偏好数据，训练 6B 参数的奖励模型
  3. PPO：奖励模型打分，强化学习优化

投入：40 名全职标注人员，数万小时标注时间，数万 A100 小时训练。

结果：175B InstructGPT 在 85% 情况下比 GPT-3 更好。

启示：ChatGPT 的成功不只是模型大，更在于对齐做得好。

Llama 3（Meta） ​

做法：

  1. SFT：高质量合成数据 + 人工筛选
  2. 对齐：主要使用 DPO，而不是 RLHF

为什么选择 DPO？ 训练更稳定、不需要维护奖励模型、效果足够好、适合开源复现。

结果：DPO 对齐后明显优于 SFT 版本。

启示：开源界趋势从 RLHF 转向 DPO。Llama 3 选择 DPO 是刻意选择。

DeepSeek 和 Qwen ​

DeepSeek：多轮 DPO 对齐（迭代式），利用合成数据增强偏好数据。 Qwen（通义千问）：SFT + DPO 组合，特别重视中文偏好数据质量。

12. 本课总结 ​

  • 偏好数据 = 问题 + 多个回答 + 好坏标注，教模型"什么回答更好"
  • SFT 教对错，DPO/RLHF 教好坏
  • DPO：直接用好/差回答对优化，简单、稳定、便宜
  • RLHF：先训练奖励模型打分，再用强化学习优化，复杂但上限可能更高
  • 奖励模型 = 自动打分器，替代昂贵的人工标注
  • 选型原则：大部分场景 SFT + DPO 已经足够
  • 开源数据集：HelpSteer、UltraFeedback、HH-RLHF
  • 常见陷阱：噪音、过度对齐、奖励欺骗、成本低估
  • 行业案例：ChatGPT 用 RLHF（大规模投入），Llama 3 用 DPO（更实际的选择）

13. 心智模型 ​

把模型想象成一个实习生。SFT 是让他背了标准答案。DPO 是告诉他"同样的题目，这样做比那样做更好"。RLHF 是给他配了一个经验丰富的导师，每次做完都打分指导。

不要追求"最先进的技术"，要追求"最适合你团队和技术条件的方法"。

14. 初学者常见错误 ​

错误 1：跳过 SFT 直接做 DPO ​

DPO 需要在 SFT 之后的模型上进行。SFT → DPO → RLHF，顺序不能乱。

错误 2：偏好数据全是"明显好坏" ​

好回答 500 字、差回答 5 个字——模型学到的是"长度偏好"而不是"质量偏好"。两个回答都不差但一个更好，这才是好的偏好数据。

错误 3：认为 DPO 不需要数据清理 ​

好回答有事实错误、差回答明明也很好、标注颠倒了——这些会让模型学歪。

错误 4：RLHF 训练时不做监控 ​

RLHF 容易跑崩。需要监控奖励分数、回答长度、KL 散度、人工抽检质量。

RLHF 像开赛车——快但容易翻车。DPO 像开家用车——没那么快但稳。

15. 小练习 ​

打开 Hugging Face 上的 HelpSteer 数据集（nvidia/HelpSteer）：

  1. 浏览 10 条数据，看每条包含哪些字段
  2. 对比 chosen 和 rejected 的差异——标注者的判断合理吗？
  3. 有没有你觉得"chosen 不如 rejected"的数据？说明理由
  4. 统计 chosen 回答的平均字数是否比 rejected 多
  5. 如果让你用这个数据集做 DPO，你会先做哪些清理？

16. 小项目 ​

构建一个你自己的小规模偏好数据集（20 条就够了）：

  1. 选主题：你的专业领域（产品管理、编程、咖啡、健身……）
  2. 写 10 个问题：覆盖解释概念、写文案、解决问题、创意写作
  3. 为每个问题写两个回答：一个好回答 + 一个差回答（"不够好"而非"错误"）
  4. 用 DPO 格式保存：
json
[
  {
    "prompt": "用一句话说明什么是用户体验设计",
    "chosen": "用户体验设计是以用户为中心的设计方法，关注产品如何让用户高效、愉快地完成任务。",
    "rejected": "用户体验设计就是让产品好看好用。"
  },
  {
    "prompt": "写一个产品经理的周报开头",
    "chosen": "本周重点推进了用户增长实验和支付流程优化。核心指标：新增用户 +12%，支付成功率提升至 89%。",
    "rejected": "这周做了几个事情，总体还行。"
  }
]
  1. 自我检查：好/差回答差距别太大、差回答无事实错误、好回答是你真想要的风格。

完成后，你就拥有了一份可以直接用来做 DPO 训练的数据集！
