第 9 课：合成数据和数据清洗 ​

本课目标：理解什么是合成数据、为什么需要它，学会数据清洗和去重的核心方法，掌握构建高质量训练数据集的完整流程。

1. 先说结论 ​

训练一个好模型，数据比算法重要。

但优质数据从哪来？人工写太慢、太贵。互联网爬的不够干净、不够精准。

答案就是：用 AI 帮 AI 生成数据——这就是合成数据。

但合成数据不是"让 AI 随便写一堆话就行"。它像盖楼——你可以用机器搅拌水泥，但不能把垃圾也倒进去。

所以这一课讲两件事：

  1. 合成数据——怎么用 AI 生成高质量的"问题-回答"对
  2. 数据清洗——怎么过滤掉垃圾、去掉重复、把格式统一

一句话：合成数据解决"数据不够"的问题，数据清洗解决"数据太脏"的问题。

2. 生活类比 ​

类比 1：饺子馆老板 ​

假设你开了一家饺子馆，雇了 10 个新厨师需要培训。

人工标注数据 = 你一个一个地给厨师演示怎么包饺子。包得对，但太慢。包 10000 个饺子你得累死。

合成数据 = 让一个老厨师先包 100 个标准饺子当"样板"，然后让新厨师照着样板自己包。你在旁边看着，教他们怎么模仿。快，但新厨师可能包歪了。

数据清洗 = 饺子包好了，你把破皮的、馅太少的、形状歪的挑出来扔掉。留下的才是能端上桌的。

类比 2：学校出考题 ​

你要出一套 100 道题的期末考试卷。

人工写题 = 你亲自出 100 道。质量高，但你累得不行。

合成数据 = 你写 5 道模板，让 AI 模仿风格出剩下的 95 道。然后你去检查——把超纲的删掉，把有错的改掉，把重复的去掉。

留下的 80 道题，才是"可用的合成数据"。

3. 什么是合成数据？ ​

3.1 定义 ​

合成数据（Synthetic Data） 就是用程序、规则或模型自动生成的数据，而不是从现实世界中采集的。

对于 LLM 训练来说，合成数据主要指用一个大模型（比如 GPT-4、DeepSeek）来生成"问题-回答"对，用来训练另一个模型。

3.2 为什么需要合成数据？ ​

问题说明
人工标注太贵雇人写 10 万条高质量问答，可能要花几十万人民币
人工标注太慢一个人一天可能只写 50-100 条
互联网数据不干净网上爬的对话质量低、有噪音、格式乱
特定领域难覆盖比如"肝脏影像学诊断"这类专业问题，网上很少
需要大量数据现代微调动辄需要几万到几十万条数据

合成数据的优势就是：便宜、快速、可扩展。

3.3 合成数据的风险 ​

合成数据不是万能的。也有坑：

风险说明
模型"自产自销"用 GPT-4 造数据训练小模型，小模型学到的只是 GPT-4 的"影子"
错误传播老师模型答错了，学生模型也学错
缺乏多样性AI 生成的风格比较单一，不像人类那么多变
重复率高AI 容易生成结构相同的话

好的做法是：合成数据 + 人工审查，而不是完全交给 AI。

4. 合成数据生成的三大策略 ​

4.1 Self-Instruct（自我指令） ​

核心思路：用一个 seed（种子）数据集 + 一个模型，让模型自己生成数据。

流程：

种子数据（少量人工写的问答对）
       ↓
让模型阅读种子，生成更多类似的问题
       ↓
针对每个问题，让模型自己回答
       ↓
过滤低质量数据
       ↓
得到批量问答对

优点：简单、启动快。只需要几十条种子数据。

缺点：生成的多样性有限，容易局限在种子数据的范围里。

Self-Instruct 是 2022 年斯坦福的 Alpaca 项目用的方法。他们只用 175 条种子数据就生成了 52000 条训练数据。

4.2 Evol-Instruct（进化指令） ​

核心思路：把简单问题一步步"进化"成复杂问题。

先有一个简单问题：

"什么是机器学习？"

然后让 AI 让它变复杂：

第一轮：加约束
→ "用三个比喻解释什么是机器学习，每个比喻不超过 20 个字"

第二轮：加深度
→ "解释机器学习、深度学习、强化学习的区别，给每个举一个实际应用场景"

第三轮：加多步推理
→ "用户想开一家奶茶店。请用机器学习的方法帮他预测开在哪、开多大、定什么价。每一步推理都说明为什么。"

优点：生成的问题质量高、难度层次丰富。

缺点：多轮进化耗时较长，需要多次调用大模型。

Evol-Instruct 是 WizardLM 项目的核心方法。

4.3 Magpie 方法 ​

核心思路：利用模型本身的"好奇心"来生成数据。

做法很巧妙：给模型一个空对话，它自己就会好奇"用户会问什么"，然后自动生成问题和回答。

模型看到的 prompt：
"以下是用户和 AI 助手之间的对话。"

模型开始自己生成：
→ "用户：什么是量子计算？"
→ "助手：量子计算是利用量子比特进行计算的技术……"

优点：完全不需要种子数据，模型自己生成各种问题。

缺点：可控性差，生成的话题可能太发散。

4.4 其他策略 ​

策略描述
翻译回译把英文数据翻译成中文，再翻译回去验证质量
话题扩散从一个关键词出发，让模型生成相关话题的问题
文档反推给一段文档，让模型根据文档内容生成问答对
角色扮演让模型扮演"专家"和"新手"，自动生成对话

4.5 策略选择建议 ​

场景推荐策略
你需要快速获取大量通用数据Self-Instruct
你需要高质量、有层次的数据Evol-Instruct
你想探索新领域、不想被种子限制Magpie
你有行业文档/手册文档反推
你想提升某个垂直领域的数据覆盖话题扩散

5. 数据清洗——什么是数据清洗？ ​

5.1 定义 ​

数据清洗（Data Curation / Data Cleaning） 就是把原始数据中的"垃圾"去掉，让数据变得更干净、更一致、更有用。

不管你用合成数据还是人工数据，这一步都不能跳。

5.2 为什么需要数据清洗？ ​

你想想，你用 Self-Instruct 生成了 10 万条数据——里面可能有：

  • 重复的问题问了 300 次
  • 回答里夹着"作为一个 AI 模型，我……"
  • 格式混乱，一半用 markdown 一半用纯文本
  • 事实错误——比如说"中国的首都是上海"
  • 内容太短，只有 3 个字的"回答"

如果直接拿这些数据训练，模型会学出各种坏习惯。

脏数据进，脏模型出。Garbage In, Garbage Out。

6. 常见数据质量问题 ​

问题示例为什么有害
噪音回答里有多余的 HTML 标签、乱码模型学不会干净输出
重复同一问题出现几十次模型在单一问题上过拟合
事实错误回答"中国有 56 个民族"写成了"55 个"模型记住错误知识，很难纠正
格式混乱一半用 bullet、一半用数字、一半用段落模型输出风格不稳定
太短用户问"解释 Transformer"，回答"它是机器学习模型"训练效果差，没学到内容
太长回答写了 5000 字，大部分是废话模型学不会简洁表达
自指回答里有"作为一个 AI，我……"学出"AI 自恋"的毛病
敏感内容回答包含暴力、违法内容模型不安全

7. 数据清洗的四大技术 ​

7.1 去重（Deduplication） ​

后面第 11 节会详细讲。这里先提一句：去掉重复数据是最简单、最有效的清洗手段。

7.2 长度过滤 ​

去掉太短和太长的数据。

python
def length_filter(data, min_tokens=10, max_tokens=2048):
    """过滤掉 token 数量不在范围内的数据"""
    filtered = []
    for item in data:
        tokens = count_tokens(item["output"])
        if min_tokens <= tokens <= max_tokens:
            filtered.append(item)
    return filtered

经验值：

数据类型最短长度最长长度
简单问答10 个 token512 个 token
复杂推理50 个 token2048 个 token
多轮对话每轮最少 5 个 token4096 个 token

7.3 语言/内容过滤 ​

  • 语言检测：确保数据是你想要的语言（比如中文数据里混了英文和日文）
  • 关键词过滤：去掉包含敏感词、脏话的数据
  • URL 过滤：去掉回答里全是链接的数据
  • PII 过滤：去掉包含身份证号、手机号等个人隐私的数据
python
def keyword_filter(data, blacklist=["test", "placeholder", "TODO", "lorem ipsum"]):
    """去掉包含黑名单关键词的数据"""
    return [item for item in data if not any(w in item["output"] for w in blacklist)]

7.4 质量评分 ​

这是最"高级"的清洗方式——用 AI 给数据打分。

流程：

1. 选一个质量评估模型（比如 GPT-4、DeepSeek、或专门的评分模型）
2. 对每条数据，让评估模型打分（1-5 分）
3. 只保留分数高于阈值的数据（比如 4 分以上）

评分维度可以包括：

维度评分说明
有帮助性回答是否真正解决了用户的问题
准确性回答是否包含事实错误
完整性回答是否完整，而不是只说一半
格式格式是否正确、易读
安全性是否包含不安全内容

用大模型来评分，虽然需要成本，但比你肉眼看 10 万条数据快得多。

8. 为什么数据质量比数量更重要 ​

这是 LLM 训练中最重要的一条原则。说三遍：

数据质量 > 数据数量

数据质量 > 数据数量

数据质量 > 数据数量

8.1 数据实验对比 ​

数据集数据量训练效果
A50 万条（自动爬取，未清洗）模型回答质量一般，有很多噪音
B2 万条（高质量人工标注）模型回答清晰、准确
C10 万条（合成 + 严格清洗）模型效果接近 B

实验表明：2 万条干净数据的效果，可能超过 50 万条脏数据。

8.2 为什么？ ​

  1. 脏数据让模型学坏：一条错误数据 = 十次正确数据的负面影响
  2. 重复数据无意义：模型从第 10 次重复中学不到新东西
  3. 多样性才是关键：1000 条不同场景的好数据，比 10000 条同一个场景的数据有价值

8.3 什么时候数量重要？ ​

只有一种情况数量重要：你已经保证了基本质量。

就像做菜——先保证每道菜味道没问题，再考虑多做几道菜。而不是先做 100 道菜，一半是糊的。

9. 数据集去污染——去掉测试集重叠 ​

9.1 什么是数据污染？ ​

数据污染（Data Contamination / Data Leakage） 是指训练数据里包含了测试数据的内容。

比如你要做一个"法律问答"模型，准备了 10 万条训练数据和 5000 条测试数据。

但是——那 5000 条测试数据中的一些问题和答案，也出现在你的训练数据里。

结果：

  • 模型在测试集上得分很高，但那是"作弊"
  • 上了真实场景，效果一落千丈

9.2 为什么容易发生？ ​

  • 你从网上爬的数据，可能已经包含了某些公开测试集
  • 合成数据生成的问答，可能恰好和公开数据集重复
  • 数据来源交叉，你没有注意

9.3 解决办法：n-gram 匹配 ​

最常用的方法是n-gram 重叠检测：

  1. 把你的训练数据和测试数据都切成 n-gram（比如 13-gram，13 个词一组）
  2. 检查训练数据里是否出现了测试数据中的 n-gram
  3. 如果某个训练样本和测试集有超过 80% 的 n-gram 重叠，就删掉或修改
python
def detect_contamination(train_text, test_texts, n=13, threshold=0.8):
    """检测训练数据和测试数据是否重叠"""
    train_ngrams = set(generate_ngrams(train_text, n))
    
    for test_text in test_texts:
        test_ngrams = set(generate_ngrams(test_text, n))
        overlap = len(train_ngrams & test_ngrams) / len(test_ngrams)
        if overlap > threshold:
            return True  # 存在污染
    return False

大部分开源模型（比如 Llama、Mistral）都有专门的去污染处理环节。

10. 数据格式化和对话模板 ​

10.1 为什么要统一格式？ ​

你的训练数据可能来自不同来源：

  • 合成数据（Self-Instruct 格式）
  • 人工标注数据（JSON 格式）
  • 网上爬的对话（ShareGPT 格式）
  • 单轮问答（Alpaca 格式）

这些格式在进入训练之前，必须统一成模型能理解的对话模板（Chat Template）。

10.2 什么是 Chat Template？ ​

Chat Template 就是把对话转成模型需要的格式。

不同模型的模板不同：

模型对话模板示例
Llama 3`<
ChatML`<
DeepSeek`<

10.3 用 Hugging Face 自动转换 ​

你不需要手动写模板。Hugging Face 的 apply_chat_template 可以自动处理：

from transformers import AutoTokenizer

11. 去重方法详解 ​

11.1 为什么要去重？ ​

假设你生成了 50 万条合成数据。但实际统计后发现，有效数据可能只有 10 万条——因为：

  • 同样的"解释什么是 Transformer"出现了 500 次
  • 只是措辞不同，本质是一样的
  • 模型在重复数据上反复学习，会忽略小众但重要的话题

11.2 去重的三个层级 ​

层级方法效果速度
第一层精确匹配去重去掉完全一样的数据最快
第二层模糊去重（Near-Dedup）去掉几乎一样的数据中等
第三层MinHash / LSH去掉语义相似的数据较慢但全面

11.3 精确匹配去重 ​

最简单：如果两句话一模一样，只保留一条。

python
def exact_dedup(data):
    """精确去重"""
    seen = set()
    unique = []
    for item in data:
        text = item["instruction"] + item["output"]
        if text not in seen:
            seen.add(text)
            unique.append(item)
    return unique

缺点：改一个标点、加一个空格就识别不出来了。

11.4 模糊去重（Near-Dedup） ​

去掉"几乎一样"的数据。常用方法有：

方法一：编辑距离

  • 两句话之间的"编辑次数"（增/删/改一个字符算一次）
  • 编辑距离 < 某个值就认为是重复

方法二：Jaccard 相似度

  • 把句子切成 n-gram 集合
  • 计算两句话的 n-gram 集合重合度
  • Jaccard 相似度 = 交集大小 / 并集大小
"什么是机器学习" → {"什么是", "是机器", "机器学", "器学习"}
"什么是深度学习" → {"什么是", "是深度", "深度学", "度学习"}

相似度 = 交集{什么是} / 并集{什么是, 是机器, ...}
       = 1 / 7 ≈ 14%  不算重复

11.5 MinHash + LSH（工业级去重） ​

这是目前用得最广的去重方法，适合大数据量。

MinHash 是一种把"文本相似性"转换成"哈希碰撞概率"的算法。

流程：

1. 把每条数据变成一组 shingles（n-gram 集合）
2. 用多个哈希函数给每个集合"签名"
3. 两条数据签名越相似，内容越接近
4. 用 LSH（局部敏感哈希）把相似数据分到同一桶里
5. 桶内的数据互相比较，去掉重复
python
# 用 datasets 库实现 MinHash 去重（伪代码）
from datasets import Dataset
from datasketch import MinHash, MinHashLSH

def minhash_dedup(dataset, num_perm=128, threshold=0.8):
    """用 MinHash 去重"""
    lsh = MinHashLSH(threshold=threshold, num_perm=num_perm)
    
    for i, item in enumerate(dataset):
        # 为每条数据创建 MinHash 签名
        m = MinHash(num_perm=num_perm)
        for word in item["text"].split():
            m.update(word.encode('utf-8'))
        lsh.insert(f"doc_{i}", m)
    
    # 找到重复的文档
    duplicates = set()
    for i, item in enumerate(dataset):
        m = MinHash(num_perm=num_perm)
        for word in item["text"].split():
            m.update(word.encode('utf-8'))
        result = lsh.query(m)
        # 如果结果里有其他文档，说明有重复
        if len(result) > 1:
            duplicates.add(f"doc_{i}")
    
    # 去掉重复
    kept = [item for i, item in enumerate(dataset) 
            if f"doc_{i}" not in duplicates]
    return kept

实际项目中，大多数情况下用现成的库，不需要自己写 MinHash。推荐：

  • datasets 库自带去重工具
  • text-dedup 库专门做文本去重
  • datasketch 库提供 MinHash 实现

12. 数据混合比例——怎么配比数据 ​

12.1 什么是数据混合（Data Mixing）？ ​

你手上有多个来源的数据：

  • 通用问答数据（20 万条）
  • 数学推理数据（5 万条）
  • 代码数据（10 万条）
  • 翻译数据（3 万条）
  • 领域专业数据（2 万条）

你不能简单地全部扔进训练——那样模型会被"通用问答"淹没，数学能力很差。

数据混合比例就是决定每种数据放多少的策略。

12.2 常见混合策略 ​

策略做法适合场景
平均分配每种数据比例相同通用模型
任务加权重要的任务多放数据有核心任务的场景
课程学习先简单后难训练复杂推理能力
动态调整根据训练效果动态调比例高级场景

12.3 经验比例参考 ​

数据类型通用助手代码助手领域专家
通用对话40%20%20%
推理/数学20%10%15%
代码15%50%5%
创意写作10%5%5%
领域数据5%5%50%
安全/拒绝回答5%5%5%
翻译/多语言5%5%0%

注意：这只是参考值。实际比例需要通过实验调整。

12.4 比例调优的步骤 ​

1. 用 80/20 经验法则做初始比例
2. 先做一小批训练（比如 5000 条的总量）
3. 在验证集上测试各维度效果
4. 哪方面弱就增加哪种数据的比例
5. 重复直到平衡

13. 实用数据准备管道 ​

把上面的知识串起来，一个完整的数据准备流程如下：

13.1 整体流程 ​

开始
  ↓
① 数据收集 / 生成
    ├─ 人工标注数据
    ├─ 合成数据（Self-Instruct / Evol-Instruct / Magpie）
    └─ 开源数据
  ↓
② 初步清洗
    ├─ 语言过滤（只保留中文/英文）
    ├─ 长度过滤（去掉太短太长）
    └─ 敏感内容过滤
  ↓
③ 去重
    ├─ 精确匹配去重
    └─ MinHash 模糊去重
  ↓
④ 质量评分与过滤
    └─ 用评分模型打分，保留下高分数据
  ↓
⑤ 去污染
    └─ 检查与测试集是否有重叠
  ↓
⑥ 统一格式
    └─ 转换为目标模型的 Chat Template 格式
  ↓
⑦ 数据混合
    └─ 按比例混合不同类型的数据
  ↓
⑧ 最终检查
    └─ 随机抽取 100 条人工审查
  ↓
准备好训练！

13.2 实际代码示例 ​

python
def data_preparation_pipeline(raw_data, config):
    """完整的数据准备流程"""
    
    # 1. 长度过滤
    data = [d for d in raw_data if config["min_len"] <= len(d["output"]) <= config["max_len"]]
    
    # 2. 语言过滤（使用 langdetect 或 fasttext）
    data = [d for d in data if detect_language(d["output"]) == config["target_lang"]]
    
    # 3. 精确去重
    data = exact_dedup(data)
    
    # 4. MinHash 模糊去重
    data = minhash_dedup(data, threshold=config["dedup_threshold"])
    
    # 5. 质量评分（用 GPT-4 或评分模型）
    data = quality_score_filter(data, min_score=config["min_quality_score"])
    
    # 6. 去污染
    data = remove_contaminated(data, test_set=config["test_set"])
    
    # 7. 格式转换
    data = apply_chat_template(data, model_name=config["model_name"])
    
    print(f"最终数据量：{len(data)} 条")
    return data

15. 本课总结 ​

  • 合成数据 = 用 AI 生成训练数据。三大策略：Self-Instruct、Evol-Instruct、Magpie
  • 数据清洗 = 去噪音、去重复、过滤低质量数据
  • 数据质量 > 数据数量——2 万条干净数据好过 50 万条脏数据
  • 去重有三个层次：精确匹配、模糊去重、MinHash/LSH
  • 去污染：训练数据不能包含测试集内容
  • Chat Template：所有数据要统一成模型能理解的对话格式
  • 数据混合：按比例搭配不同类型的数据，不要偏科
  • 完整流程：收集 → 初洗 → 去重 → 评分 → 去污染 → 格式化 → 混合 → 人工抽查

16. 心智模型 ​

合成数据和数据清洗——就像在做一个"食材加工厂"。

合成数据是你的"原料机器人"，帮你快速产出大量食材（问答数据）。

数据清洗是你的"质检流水线"——把坏掉的、重复的、不合适的食材挑出来扔掉。

数据混合是你的"配菜师傅"——决定每种菜放多少胡萝卜、多少肉。

最后出来的，才能成为一道好菜（好模型）。

没有好的原料和干净的加工，再好的厨师（算法）也做不出好菜。

17. 初学者常见错误 ​

错误 1：完全不信任合成数据 ​

"合成数据是假的，不能用。"

事实：合成数据在大多数场景下效果很好。关键是配合人工审查和清洗。

错误 2：完全不看数据质量 ​

"只要量大就行，10 万条训练数据肯定比 1 万条好。"

事实：前面说了很多次——数据质量 > 数据数量。垃圾进，垃圾出。

错误 3：忘记去污染 ​

训练完模型后，在公开测试集上效果很好，但上了线就崩了。

原因：训练数据里包含了测试集的题目。

错误 4：数据混合比例随意 ​

"通用问答 100 万条，代码 1 万条——反正都是数据。"

结果：模型只会聊天，完全不会写代码。

错误 5：格式不统一 ​

数据来自 5 个来源，5 种格式。直接丢进训练——模型输出混乱，一半时间不知道自己在回答谁。

错误 6：只用一种合成策略 ​

只用 Self-Instruct，生成的 10 万条数据风格一模一样。

结果：模型只会"按模板说话"，缺乏灵活性。

正确做法：多用几种策略，混合使用。

错误 7：合成数据没做质量评分 ​

"反正是 GPT-4 生成的，质量不可能差。"

事实：GPT-4 也会犯错、也会生成废话、也会重复。一定要做质量过滤。

18. 小练习 ​

  1. 打开 Hugging Face，找一个开源数据集（比如 Alpaca 或 OpenAssistant）
  2. 统计有多少条数据包含"作为一个 AI"或"作为一个语言模型"
  3. 计算数据集中"instruction"字段的重复率（精确匹配）
  4. 随机抽取 20 条数据，人工打质量分（1-5 分）
  5. 找出你认为最差的 3 条和最好的 3 条

19. 小项目 ​

用 GPT-4（或其他大模型 API）生成一个小型合成数据集：

目标：生成 100 条关于你熟悉领域的"问题-回答"对。

步骤：

  1. 选择一个小领域（比如：咖啡、跑步、宠物护理、Notion 使用技巧）
  2. 写 5 条种子数据（人工写好）
  3. 用 Self-Instruct 方法，让 GPT-4 根据种子生成 50 条新问题
  4. 再用 Evol-Instruct 方法，把 5 条简单问题进化成复杂问题，生成另外 50 条
  5. 做基本清洗：
    • 去掉长度 < 20 字或 > 500 字的数据
    • 去掉完全重复的问题
    • 手动检查 20 条，标记质量差的
  6. 保存为 JSON 文件，格式：
json
[
  {
    "id": 1,
    "instruction": "手冲咖啡的水温应该保持在多少度？",
    "output": "一般建议 90-96°C。深烘焙用偏低温度（90-92°C），浅烘焙用偏高温度（93-96°C）。",
    "quality_score": 5,
    "source": "evol-instruct"
  }
]

完成后，你就走了一遍企业做合成数据的完整流程。
