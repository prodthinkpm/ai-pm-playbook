第 7 课：SFT 数据集和指令微调 ​

本课目标：理解什么是 SFT 数据集，什么是指令微调，以及如何通过数据把一个"只会补全文字"的 base model 教成"能听懂指令、能回答问题"的助手。

1. 先说结论 ​

训练 LLM 大致分两步：

第一步：预训练

模型读海量互联网文字，学会语言规律。这时的模型叫 base model（基础模型）。

它只能做一件事：

用户：中国的首都是
模型：北京

因为它只学会了"预测下一个词"。它不会回答问题，不会闲聊，不会遵守指令。

第二步：指令微调

用高质量的"问题-回答"对数据，让模型学会听懂指令并给出有用回答。

这步叫做 SFT——Supervised Fine-Tuning，有监督微调。

简单说：SFT 就是把一个"只会补全的模型"教成"一个能对话的助手"。

2. 生活类比 ​

类比 1：医学院学生 ​

预训练 = 读了很多很多书，但没上过临床。

SFT 指令微调 = 进入实习阶段，跟着导师看真实病例，学习病人问了问题应该怎么回答。

读了再多书，不实习还是不会看病。

SFT 就是那个"实习期"。

类比 2：厨师的学徒 ​

预训练 = 你背下了所有菜谱、食材、烹饪原理。

SFT = 你站在厨师旁边，看着他做菜。他问你：

学徒：醋应该在什么时候放？
厨师：起锅前放，不能太早。

下一次，当客人问你"菜为什么酸了"，你开始知道怎么回答。

SFT 就是用大量"问答例子"训练模型的对话能力。

3. Base Model vs Instruction-Tuned Model ​

先看清区别：

对比Base Model（基础模型）Instruction-Tuned Model（指令微调后）
训练方式预训练（读大量文字）预训练 + SFT
能力预测下一个 token回答问题、遵守指令
是否适合聊天❌ 不适合✅ 适合
是否适合 API 产品❌ 不适合✅ 适合
实际例子Llama-3-8B（基础版）Llama-3-8B-Instruct
使用方式需要写特殊 prompt 结构直接像聊天一样使用

你平时用到的 ChatGPT、Claude、Gemini 都是 instruction-tuned 之后的模型。

4. 什么是 SFT 数据集？ ​

SFT 数据集就是大量"指令-回答"对。

每一对数据包含：

用户输入（指令/问题）→ 期望输出（正确回答）

例如：

用户：用简单语言解释什么是机器学习。
回答：机器学习是让计算机从数据中学习规律，而不是靠人写规则。
用户：写一封请假邮件，理由是感冒。
回答：尊敬的领导，我因感冒身体不适，申请明天请假一天。期间我会保持手机畅通，有需要随时处理。谢谢。

数据集的规模从几千条到几百万条不等。

质量比数量重要得多。1000 条高质量数据，效果可能超过 10 万条低质量数据。

5. SFT 数据集的常见格式 ​

不同工具和框架使用不同格式。你不需要一开始全部记住，但要知道它们长什么样。

格式 1：Alpaca 格式 ​

一个 JSON 文件，每条包含 instruction、input（可选）、output：

json
{
  "instruction": "用简单语言解释什么是机器学习",
  "input": "",
  "output": "机器学习是让计算机从数据中学习规律，而不是靠人写规则。"
}

如果 input 不为空，模型需要结合 instruction 和 input 一起理解：

json
{
  "instruction": "解释下面这句话",
  "input": "人工神经网络是一种计算模型",
  "output": "这句话的意思是：人工神经网络是一种仿照人脑结构设计的计算系统。"
}

格式 2：ShareGPT 格式 ​

模拟多轮对话，每条包含多组对话：

json
{
  "conversations": [
    {
      "from": "human",
      "value": "什么是 token？"
    },
    {
      "from": "gpt",
      "value": "Token 是模型读文字时用的小块。一个中文字可能就是一个 token，一个英文单词可能被切成多个 token。"
    },
    {
      "from": "human",
      "value": "那上下文窗口是什么？"
    },
    {
      "from": "gpt",
      "value": "上下文窗口是模型一次能看到的 token 数量上限。比如 8K 窗口意味着模型最多看 8000 个 token。"
    }
  ]
}

格式 3：对话模板格式（Chat Template） ​

实际训练时，数据会被转换成模型能理解的统一格式：

<|user|>
什么是 token？
<|assistant|>
Token 是模型读文字时用的小块。
<|user|>
那上下文窗口呢？
<|assistant|>
上下文窗口是模型一次能看到的 token 数量上限。

不同模型的对话模板不一样。比如：

  • Llama 用 <|begin_of_text|><|start_header_id|>user<|end_header_id|>
  • ChatML 用 <|im_start|>user
  • DeepSeek 用 <|User|>

你不必自己写模板。Hugging Face 的 apply_chat_template 会自动帮你转换。

6. 指令微调的核心逻辑 ​

SFT 不是什么魔法。它的核心是：

让模型在"看到问题 → 生成回答"这条路径上，不断学习正确的模式。

训练过程大致如下：

text
原始模型参数 → 随机初始化
           ↓
输入数据：[用户问题]
           ↓
模型生成回答（此时回答可能很糟糕）
           ↓
拿模型回答和"正确回答"对比
           ↓
计算差距（loss）
           ↓
调整模型参数，减少差距
           ↓
重复……直到模型能稳定输出好回答

技术上说，SFT 就是在做 next token prediction——和预训练一样。

区别在于：

预训练SFT
数据大量互联网文本少量"问题-回答"对
目标学会语言规律学会听指令回答
效果能补全文字能对话、能回答问题

7. 什么时候需要 SFT？ ​

不是所有场景都需要 SFT。

需要 SFT ​

  • 你希望模型按特定风格回答（比如"语气像客服"）
  • 你需要模型掌握特定领域的知识
  • 你有很多高质量问答数据
  • prompt 工程已经到极限了
  • 模型经常在某一类问题上出错

不需要 SFT（用 Prompt / RAG 就够了） ​

  • 问题简单，给几个例子就能搞定
  • 你每次可以把资料放进 prompt
  • 模型已经够好了
  • 没有高质量数据

一般建议：先用 prompt 工程，再试 RAG，最后才考虑 SFT。SFT 不是第一步。

8. 数据准备的核心注意事项 ​

SFT 的效果 90% 来自数据质量。

质量第一 ​

一条高质量数据比十条低质量数据更有用。

好的数据：

用户：什么是向量数据库？
回答：向量数据库是专门用来存储和搜索 embedding 的数据库。它通过"语义距离"来找相似内容，而不是通过精确匹配。

差的数据：

用户：什么是向量数据库？
回答：向量数据库是一种数据库。

太模糊、太短、没有信息量的回答，对训练没有帮助。

多样性 ​

你的数据应该覆盖多种场景：

  • 简单问题
  • 复杂问题
  • 需要多步推理的问题
  • 创意写作
  • 代码生成
  • 总结
  • 翻译
  • 拒绝回答（当用户问不合适的问题时）

格式一致性 ​

所有数据的格式要统一。如果一半用"帮我写……"开头、一半是句子、一半是代码，模型会困惑。

不要有事实错误 ​

训练数据一旦有错误，模型会学到错误知识，而且很难修正。

避免重复 ​

重复数据会让模型在某个问题上过度学习，影响其他能力。

9. 数据集规模的经验值 ​

目标推荐数据量
简单风格调整几百条 ~ 几千条
特定任务优化1k ~ 10k 条
通用助手能力10k ~ 100k 条
达到 GPT 级别100k ~ 1M+ 条

但注意：

100 条极其优质的数据，效果可能超过 10 万条粗制滥造的数据。

先做小规模实验，确认质量有效，再扩大。

工具适合场景难度

11. 本课总结 ​

  • Base model 只会预测下一个词，不会对话
  • SFT 指令微调 让模型学会听指令、回答问题
  • SFT 数据集 = 大量"指令-回答"对
  • 常见格式有 Alpaca、ShareGPT、Chat Template
  • 数据质量 > 数据数量，永远是第一原则
  • 先用 prompt 工程和 RAG，最后才考虑 SFT
  • 微调的工具：TRL、Axolotl、Unsloth、Llama Factory

12. 心智模型 ​

SFT 就像是给一个"背完百科全书的人"做上岗培训。

他不是不懂知识，而是需要学会怎么和人对话、怎么回答问题。

SFT 数据集就是你的培训手册——每一道题都配了标准答案。模型反复练习，直到学会正确的回答方式。

13. 初学者常见错误 ​

错误 1：以为 SFT 是训练模型的全部 ​

SFT 只是第二步。

完整的流程通常是：预训练 → SFT → 偏好对齐（DPO/RLHF）。

错误 2：忽略数据质量，只追求数量 ​

10 万条垃圾数据 = 垃圾模型。

错误 3：数据集太单一 ​

全部数据都是"解释概念"类的，模型就只会解释概念，不会做其他事。

错误 4：把基座模型直接当聊天模型用 ​

Base model 不适合直接对话。没做 SFT 的模型不会遵守指令。

错误 5：SFT 数据包含错误 ​

用户问"什么是 RAG"，你的训练数据回答的是"RAG 是一种拉格"——那模型就会学错。

错误 6：训练数据格式不统一 ​

一半数据用"帮我……"，一半是"请……"，一半是直接问句——模型输出也会混乱。

14. 小练习 ​

找一个开源的 SFT 数据集，比如：

Hugging Face 上的 Alpaca 数据集
或 OpenAssistant 数据集

看看：

  1. 数据格式是什么样的？
  2. 每条数据包含哪些字段？
  3. 数据覆盖了哪些类型的任务？
  4. 有没有你认为质量不行的数据？
  5. 挑出 3 条好数据和 3 条差数据，说说你的理由。

15. 小项目 ​

创建一个你自己的小型 SFT 数据集（10 条就够了）：

  1. 选择你熟悉的一个领域（比如：产品管理、咖啡、健身、旅游）。
  2. 写 3 个"解释概念"的问题和回答。
  3. 写 2 个"写文案"的问题和回答。
  4. 写 2 个"解决问题"的问题和回答。
  5. 写 2 个"多轮对话"的示例。
  6. 写 1 个"需要拒绝回答"的示例（比如违法请求）。

用 Alpaca 格式保存为 JSON 文件：

json
[
  {
    "instruction": "什么是 MVP？",
    "input": "",
    "output": "MVP 是最小可行产品，是包含核心功能的最简产品版本，用于快速验证市场假设。"
  },
  {
    "instruction": "写一个健身周计划",
    "input": "目标：增肌，每周 4 练",
    "output": "周一：胸+三头\n周二：背+二头\n周四：腿+肩\n周五：胸背组合\n每次训练后加 20 分钟有氧。"
  }
]

完成这 10 条数据后，你就是亲手做了一次 AI 训练数据准备的工作。
